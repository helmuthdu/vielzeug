# AGENTS.md: Primal demo

- **No `container-type`/`@container` on grids in animated pages.** A matched `@container` rule on the equipment board made Chromium re-run query + layout in a loop: every page layout touching the subtree cost ~700ms (verified by bisecting dirty-layout costs; removing the query dropped it to ~1ms). `LoadoutGrid.vue` flips its wide layout with a `ResizeObserver` class instead. `LoadoutShareDialog.vue` still carries `container-type` (dialog-scoped, unverified cost): check before adding more.
- **The sidebar drawer's mini player is the music player's only mobile face.** Below 640px the topbar's audio trigger is gone (the navbar collapses its `end` slot behind the hamburger) and the full `AudioPlayerBar` is `display: none`, so every page load starts with no player built. The mini player's play button must stay enabled from nothing: `togglePlay` sends PLAY into the machine, which builds the player (or opens the consent banner first) and plays on ready: the machine owns this path (`player-machine.test.ts`); re-adding `:disabled="!ready"` to play reverts the drawer widget to a dead control. `player` in `use-youtube-audio.ts` is assigned when construction _starts_, but YouTube's API methods exist only after `onReady`: the 500ms poll must gate on `ready` or it throws `getPlayerState is not a function` through every tick of a slow (mobile-network) build.
- **The mobile sidebar's host strip must never catch pointers.** `App.vue` hides the sidebar's `bottom-bar` part on phones, but the `ore-sidebar` host still reserves the fixed 60px strip at the viewport foot (z-index above the phase dock's): left active it sat invisibly over the dock and stole its taps whenever the bar's buttons landed inside the strip. The host carries `pointer-events: none` with `::part(nav)`/`::part(drawer-backdrop)` re-armed: keep that split when touching the sidebar's phone styling.
- **Never put `backdrop-filter` on the phase dock's host.** The dock carries the actions menu, whose panel is `position: fixed` inside ore-menu's shadow. Per spec, `backdrop-filter` (like `filter`/`transform`) creates a containing block for fixed-position descendants — trapping the panel inside the dock and breaking its own `backdrop-filter` (the panel's frost could only sample the dock's composited interior, never the page content behind it, rendering the menu's blur invisible). The dock's wash and blur ride a `::before` pseudo-element: same visual, no containing block. Keep it that way when touching the dock's styling.
- **`runCommand`'s return value is the only "did it happen" signal; never wrap it in a `try`/`catch` that reports success on a swallow.** `runCommand` already runs through `guarded`, which turns a `PrimalDomainError` refusal into a localized toast and returns `undefined` (anything else rethrows to the app error handler). So a command that returns `undefined` did _not_ happen: gate follow-up UI on the returned value, not on "the call didn't throw". A local `run(action) { action(); return true }` helper is both redundant and wrong — it reads a refused `spendSkillPoint` as success, so the upgrade sheet closed on a spend the domain rejected, and a `saveProfile` wrapper on top of it showed "Saved" for a profile the store never wrote. `usePartyDeck` calls `runCommand` directly and keeps the branch sheet open / marks the save errored exactly when the return is `undefined`.
